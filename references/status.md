# Implementation status, known limits, evidence base, assumptions

**Implemented and verified by the scripts (adversarial audit/engineering rounds v0.5→v1.5):**
- v1.5 (prototype, branch `experiment/fast-path`): **all nine commands reviewed; the independent work is dispatched instead of serialized**. `/spec-apply` hands the **implementation** to a `spec-implementer` child from a precise brief (change id, goal per requirement, allowed files `targets`+`tests`, the reuse-first ladder) so the fresh-context rule is enforced instead of requested — a child cannot ask questions, so anything ambiguous, protected or `architecture` stays in the session, and **one implementation worker per change** (parent or child, never both); the parent verifies the diff against the brief, then launches the suite (`spec-gate`) and the tech-brief writer (`spec-walkthrough`) as background children in one batch. `/spec-verify` launches the gate plus **one read-only `spec-auditor` per active change** (cap 6) and runs the teach-back while they work, with the 3 questions asked **together**. `/spec-add` and `/spec-triage` survey with **`spec-recon`** in parallel with the human's questions (triage adds `spec-explainer` for the code side); `/spec-explain` delegates the trace to **`spec-explainer`** (note written as an artifact, parent verifies hops and delivers in its own words); `/spec-resolve` asks **every pending in one `question` round** instead of one by one (an unanswered item stays pending); `/spec-deps-graph` gets its own read-only agent. Eight agents live in `.opencode/agents/` with their own `model` + `permissions`; `/spec-gate`, `/spec-deps-graph` and `/diagram-sync` are thin commands (`agent: <id>` + `subagent: true`). **The parent vets every diff, finding and claimed `file:line`**; no child approves, signs or decides. `/spec-verify` may reuse fresh green evidence (fingerprint → static `--scope <id>`). Runtime settings that change the wall clock (`warming` prompt-cache keep-alive, `compaction`, `snapshots`) are documented in `docs/speed.md` and offered opt-in by INIT. Design, costs, published caveats + measurement protocol: `docs/speed.md`. Not yet measured against the frozen suite.

**NOT implemented (deliberate, v1.2):**
- Evidence signing/attestation (HMAC/OIDC): rejected by majority (single-dev); documented as a limit.
- Orphan-code / undeclared-dependency detection over the import graph (advisory semantic pass + codebase-memory).
- Consumer migration on breaking changes; auto-archive; a generated CI workflow (documented policy, not an asset).

**Evidence base**: the v1.0 comprehension axis is grounded in recent GenAI-assisted SE research (comprehension debt, explanation gates, skill formation, cognitive-load-aware refactoring) — predominantly novice-study populations: mechanisms transfer, effect sizes do not. Full map and caveats in the repo's `docs/evidence.md`.

**Known limits:**
- Evidence is local and per-clone, and **not tamper-proof** (unsigned): the real barrier is running `--run-tests` in CI.
- The parser is strict with `.openspec.yaml`; `config.yaml` reports unparsed lines as warnings (frontmatter is lenient by design).
- Flags (`human_approved`, `granted`, `accepted_by`) can be written by an agent if it proposes to; for `human_approved` and waivers the gate now requires the **cross-checked ADR** in `DECISIONS.md` (a line with 'approved'/'aprobado' + id as a word), plus manual discipline for the rest.
- The comprehension sign-off is a ritual record: the gate checks that the walkthrough exists, is complete, and that the sign-off keys are set — **not that understanding happened**. The real mechanism is the interactive teach-back in `/spec-verify`: keep it conversational (free recall, code-cited validation), never a checkbox session.
- `--scope` downgrades foreign reds to warnings **in the report only** (evidence and `gate_ok` are computed unfiltered); a red suite is global and non-degradable. For CI, run **without** scope.
- Citations: scope = targets+tests (directories expanded to code files).
- Zones: untracked files are detected via `git ls-files --others`; git-ignored files remain invisible.
- Subagent routing: background children return only their result; if a child fails or times out, the parent must retry or fall back to running the command in-session. **Nesting depth is one**: a child cannot dispatch its own children, which is why `/spec-apply` and `/spec-verify` run in the session (they are not `subagent: true`) and do the dispatching themselves.
- Dispatch trades tokens for wall clock: an audit child re-reads the delta spec and the target code in a fresh context, so the bill can rise while the wall clock falls. Fan-out is capped at 6; per-agent `permissions` are the ceiling on what a child can touch, and a child's findings are advisory until the parent vets their `file:line` evidence.

## Assumptions to verify (spike)

- `.openspec.yaml` tolerates extra keys without breaking `openspec validate`; the gate accepts metadata **bare or `x-`-prefixed** natively (the prefixed form wins when both are present; OpenSpec ≥1.14 strict validation recommends `x-`). Repos pick one convention and stick to it.
- `openspec schema fork` exists in the installed version.
- `opencode mcp add` syntax (local `--` / remote `--url`).
- The project's `test_command` (Android: `./gradlew test`).
- Structurizr's remote MCP is available; Docker alternative (`structurizr/mcp`).
- Command frontmatter `agent`/`model`/`subagent` behaves as documented in V2 (child session, model fallback order); the routing was not yet exercised headless.
- **v1.5 dispatch assumptions (not yet exercised end-to-end)**: custom agents in `.opencode/agents/` with `mode: subagent` are discoverable by the `subagent` tool from a command running in the session; per-agent `permissions` are enforced for `edit` and `shell`, and resource globs behave as expected (`openspec/**` denies nested paths; a shell rule like `git commit*` matches per command); a **foreground** `subagent` call blocks and returns the child's result, `background: true` notifies the parent; and nesting depth 1 means the dispatched children cannot dispatch their own. If any of these differs in the installed version, the fallback is the same everywhere: run that piece in the session and say so.
