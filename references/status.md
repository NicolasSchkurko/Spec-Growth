# Implementation status, known limits, evidence base, assumptions

**Implemented and verified by the scripts (adversarial audit/engineering rounds v0.5→v1.5):**
- v1.5 (prototype, branch `experiment/fast-path`): **scoped test loop** — `gate-check --tests-of <id>` runs only the change's declared `tests` through `test_command_scope` (`{tests}` / `{classes}`), for fast feedback while implementing; it records **no green and writes no evidence**, so `verified` still needs the full `--run-tests`. `/spec-apply` and `spec-implementer` use it as the inner loop.
- v1.5.1: **the ORDER gate is mechanical** — `accept-check.mjs <id>` refuses to return OK without human acceptance on record (and teach-back for tech briefs); `/spec-apply` runs it before dispatching implementation and `spec-implementer` runs it as its **first action**. Motivated by eval evidence (`t2-quickfix`, 2/5 runs coded before acceptance under "no ceremony" pressure) and the multi-pressure literature (knows-but-violates goes to ~99% while pressure persists — reciting the rule does not recover it; a gate the agent must run and that fails closed does).
- v1.5.1: **stdout diet** — `gate-check` caps the stdout warnings list at 5 and writes the full report to `openspec/last-gate-report.txt` (the parent's context is the scarce resource; detail belongs on disk).
- v1.5.1: **`doctor.mjs`** — preflight (node ≥18 + git fail closed; opencode CLI, Structurizr and the repo degrade explicitly), because OpenCode ships no `doctor` and the skill otherwise fails mid-flow on a missing dependency.
- v1.5.1: **encoding gate in the test suite** — every source file must be UTF-8 without BOM/U+FFFD/double-encoded pairs. The "mojibake in README/SKILL.md" finding of an external baseline scan was verified false: the files are clean; the *scanner* read UTF-8 as CP1252 (documented PowerShell 5.1 behavior). The gate keeps it true and documents the expected failure mode of CP1252 readers. **all nine commands reviewed; the independent work is dispatched instead of serialized**. `/spec-apply` hands the **implementation** to a `spec-implementer` child from a precise brief (change id, goal per requirement, allowed files `targets`+`tests`, the reuse-first ladder) so the fresh-context rule is enforced instead of requested — a child cannot ask questions, so anything ambiguous, protected or `architecture` stays in the session, and **one implementation worker per change** (parent or child, never both); the parent verifies the diff against the brief, then launches the suite (`spec-gate`) and the tech-brief writer (`spec-walkthrough`) as background children in one batch. `/spec-verify` launches the gate plus **one read-only `spec-auditor` per active change** (cap 6) and runs the teach-back while they work, with the 3 questions asked **together**. `/spec-add` and `/spec-triage` survey with **`spec-recon`** in parallel with the human's questions (triage adds `spec-explainer` for the code side); `/spec-explain` delegates the trace to **`spec-explainer`** (note written as an artifact, parent verifies hops and delivers in its own words); `/spec-resolve` asks **every pending in one `question` round** instead of one by one (an unanswered item stays pending); `/spec-deps-graph` gets its own read-only agent. Eight agents live in `.opencode/agents/` with their own `permissions`, **all pinned to one free model (`opencode/deepseek-v4.1-flash-free`)** so there is no paid/free mix to confuse — except `spec-implementer`, which declares no `model:` and runs on the session model; a model that `opencode models` lists is not necessarily runnable (probe it: `Model unavailable` / `Insufficient account funds`); `/spec-gate`, `/spec-deps-graph` and `/diagram-sync` are thin commands (`agent: <id>` + `subagent: true`). **The parent vets every diff, finding and claimed `file:line`**; no child approves, signs or decides. **Model choice, measured**: the mechanical agents started on `opencode/glm-5.3-flash-free` and it degenerated in production — literal repetition in `spec-gate`/`spec-walkthrough`/`diagram-sync`, and confabulation (an invented "spec command") in `spec-deps-graph`. The free variant of the session family, `opencode/deepseek-v4.1-flash-free`, ran the same four roles clean: repetition ratio ≤0.03, no step-cap hits, same wall clock. Every agent also carries a `steps:` cap, so a future degenerate run is cut off and forced to summarise instead of burning tokens. `/spec-verify` may reuse fresh green evidence (fingerprint → static `--scope <id>`). Runtime settings (`warming` prompt-cache keep-alive, `compaction`, `snapshots`) live in `references/operations.md`; INIT offers `warming` opt-in. **Model choice**: every mechanical agent is pinned to one free model in its own file (`.opencode/agents/<id>.md` → `model:`), easy to move; a model that `opencode models` lists is not necessarily runnable (probe it first — `Model unavailable` / `Insufficient account funds`); risky work still escalates (`kind: architecture` / tech briefs audited in-session or on a stronger model; the implementer runs on the session model). Design, costs, published caveats + measurement protocol: Not yet measured against the frozen suite. **Tests**: `quality/gates.test.mjs` (15 functional cases over the gate scripts: invariants, waivers, zones, evidence, pre-archive, board/graph/compact) and `quality/dispatch-smoke.mjs` (real CLI: command → agent → child, parent → `subagent` → child; it also found that agent `permissions` are **not** enforced by this build — read-only is contract + parent verification). `compact-archive` on a repo with no `archive/` yet is now a no-op instead of an error (the scripts' first functional test caught it).
- v1.4: **`/spec-deps-graph`** (9th command) — read-only inventory of what is **not archived**: the declared-deps Mermaid graph (shared with BOARD.md through `lib.dependencyGraph`, so the two views never drift) plus the living specs and the changes in flight; runs as a background subagent on a **free model** (`opencode/space-bunny-free`) · **scaffold `config.yaml` quotes every `rules:` item** (an unquoted `: ` made YAML read the item as a mapping and OpenSpec dropped the `proposal` rules, the tech-brief one included) · **capability reorganization documented**: a split moves requirements through a change — `## Purpose` on the new capability, `## REMOVED Requirements` with Reason + Migration on the old, `cap:` tags following, and a contradicting split entering as ⚔.
- v1.3: **reuse-first, based on [Ponytail](https://github.com/DietrichGebert/ponytail)'s implementation (MIT)** — smallest-complete-change ladder in `AGENTS.md`; `build-map.mjs` is the zero-dependency fallback map; **code-index ladder**: native LSP tool for small/medium repos, `codebase-memory` opt-in for large ones; `/spec-apply` closes with what was skipped + risks.
- v1.2: **restructure** — `SKILL.md` is a **router**: INIT/layout, scripts/flags/policy and this status page moved to `references/` (progressive disclosure) · **model routing**: `/spec-gate` and `/diagram-sync` run as background subagents on `opencode-go/space-bunny`; interactive commands inherit the session model · validated against the conformance suite (`quality/` in the repo).
- Earlier rounds (v0.5–v1.0): tech brief + comprehension sign-off and `/spec-explain` (v1.0) · `kind: refactor`, ⚔ conflicts, deps-sequenced overlaps (v0.9) · `--scope` report-only, approval ADR parsing, zone detection over real files, `--pre-archive` merge refs (v0.8) · `--tests-command` never green, committed evidence rejected, token/caches caps (v0.5–v0.7). All hardened by the adversarial audit rounds; the current behavior is what the sections below describe.

**NOT implemented (deliberate, v1.2):**
- Evidence signing/attestation (HMAC/OIDC): rejected by majority (single-dev); documented as a limit.
- Orphan-code / undeclared-dependency detection over the import graph (advisory semantic pass + codebase-memory).
- Consumer migration on breaking changes; auto-archive; a generated CI workflow (documented policy, not an asset).

**Evidence base**: the v1.0 comprehension axis is grounded in recent GenAI-assisted SE research (comprehension debt, explanation gates, skill formation, cognitive-load-aware refactoring) — predominantly novice-study populations: mechanisms transfer, effect sizes do not. Full map and caveats: `references/evidence.md` — read it **on demand** (when the human asks about the research base or a limit), never as part of the workflow.

**Known limits:**
- Evidence is local and per-clone, and **not tamper-proof** (unsigned): the real barrier is running `--run-tests` in CI.
- The parser is strict with `.openspec.yaml`; `config.yaml` reports unparsed lines as warnings (frontmatter is lenient by design).
- Flags (`human_approved`, `granted`, `accepted_by`) can be written by an agent if it proposes to; for `human_approved` and waivers the gate now requires the **cross-checked ADR** in `DECISIONS.md` (a line with 'approved'/'aprobado' + id as a word), plus manual discipline for the rest.
- The comprehension sign-off is a ritual record: the gate checks that the walkthrough exists, is complete, and that the sign-off keys are set — **not that understanding happened**. The real mechanism is the interactive teach-back in `/spec-verify`: keep it conversational (free recall, code-cited validation), never a checkbox session.
- `--scope` downgrades foreign reds to warnings **in the report only** (evidence and `gate_ok` are computed unfiltered); a red suite is global and non-degradable. For CI, run **without** scope.
- Citations: scope = targets+tests (directories expanded to code files).
- Zones: untracked files are detected via `git ls-files --others`; git-ignored files remain invisible.
- Subagent routing: background children return only their result; if a child fails or times out, the parent must retry or fall back to running the command in-session. **Nesting depth is one**: a child cannot dispatch its own children, which is why `/spec-apply` and `/spec-verify` run in the session (they are not `subagent: true`) and do the dispatching themselves.
- **Agent `permissions` are not enforced by the runtime in this build** (measured: a denied `edit` wrote a file). Read-only children hold because their prompt says so **and because the parent checks `git status` / `git diff --stat` afterwards** — that check is part of the command, not optional. Re-run `quality/dispatch-smoke.mjs` after upgrading OpenCode; if the canary is blocked, the enforcement claim can come back.
- **A cheap child can degenerate** (literal repetition, or confabulating tools it does not have). Two guards: the agents are pinned to a model that survived the four-role check (`opencode/deepseek-v4.1-flash-free`), and every agent declares a `steps:` cap — on the final step OpenCode removes the tools and forces a summary, so a loop ends in one message instead of hundreds. If a child still degenerates, re-run it or do that piece in-session.
- **A missing script is the trigger that looks like a model bug.** `/spec-deps-graph` and `/spec-gate` run repo-local scripts, so a branch that predates v1.5 (no `build-graph.mjs`, `lib.mjs` without `dependencyGraph`) leaves the child with nothing to report — and an earlier version confabulated a whole "spec command" instead of failing. Both agents now have an explicit preflight: missing `scripts/gates/` → say *"the repo's INIT predates v1.5; refresh scripts/gates/"* and stop. Refresh the scripts on **every branch**, not once per repo.
- Dispatch trades tokens for wall clock: an audit child re-reads the delta spec and the target code in a fresh context, so the bill can rise while the wall clock falls. Fan-out is capped at 6; per-agent `permissions` are the ceiling on what a child can touch, and a child's findings are advisory until the parent vets their `file:line` evidence.

## Assumptions to verify (spike)

- `.openspec.yaml` tolerates extra keys without breaking `openspec validate`; the gate accepts metadata **bare or `x-`-prefixed** natively (the prefixed form wins when both are present; OpenSpec ≥1.14 strict validation recommends `x-`). Repos pick one convention and stick to it.
- `openspec schema fork` exists in the installed version.
- `opencode mcp add` syntax (local `--` / remote `--url`).
- The project's `test_command` (Android: `./gradlew test`).
- Structurizr's remote MCP is available; Docker alternative (`structurizr/mcp`).
- Command frontmatter `agent`/`model`/`subagent` behaves as documented in V2 (child session, model fallback order); the routing was not yet exercised headless.
- **v1.5 dispatch — exercised by `quality/dispatch-smoke.mjs` (2026-10-19, free model)**: a command with `agent: <id>` + `subagent: true` runs as a background child and returns its result (PASS, ~15–85s); a parent dispatches a configured subagent through the `subagent` tool and gets its findings (PASS, ~60–130s). Two findings worth keeping: (a) a `mode: subagent` agent **cannot** be selected as a top-level `run --agent` ("Agent not found") — the smoke promotes it to `mode: all`; (b) the shared service **caches project config per path**, so re-running in a directory that previously had no `.opencode/agents/` answers from stale config — `--standalone` avoids it.
- **Agent `permissions` are NOT enforced by this build.** The smoke's canary (an agent whose only instruction is to write, with `edit` denied on `*`) created the file anyway, and reported that the deny rule did not hold. Therefore: read-only is a **contract + parent verification**, not a runtime guarantee — every command that dispatches a read-only child checks `git status --porcelain` / `git diff --stat` afterwards and reverts what is out of scope. Re-run the smoke after an OpenCode upgrade; if the canary is blocked, the docs can claim enforcement again.
