# Scripts, flags and gate policy

**Scripts**: `gate-check.mjs` — checks + evidence. Flags: `--root DIR` · `--json` · `--scope <id>` (local focus: reds **from other changes** become warnings — report only) · `--run-tests` (runs `test_command` and records green evidence; the CI mode) · `--tests-of <id>` (runs **only** that change's declared tests through `test_command_scope` — `{tests}` = quoted paths, `{classes}` = derived JVM classes; fast feedback, **no green, writes no evidence**) · `--tests-command "CMD"` (`tests-substituted` mode: **no green**; forbidden in CI) · `--pre-archive <id>` (archive preconditions; tech briefs must be complete + signed off; squash-merge → `merged_as: <sha>`) · `--diff <base>` (protected files vs git diff) · `build-board.mjs` (BOARD.md + board.json, incl. the declared-deps Mermaid graph; badge conditioned on `gate_ok`) · `build-graph.mjs` (read-only: the same deps graph + the living specs and changes in flight — the raw material for `/spec-deps-graph`) · `compact-archive.mjs --days=90 [--apply] [--force]` (yearly digest; requires a **clean, committed** folder before deleting; a repo with no `archive/` yet is a no-op; an invalid `--days` → error).

**Runtime settings (OpenCode V2)**: the one worth knowing is **`warming`** — `{"warming": true}` in `opencode.jsonc` sends a periodic keep-alive so the **provider-side prompt cache stays warm** while you pause between prompts (off by default; ~7 billable requests per 30-minute window). A Spec Growth session re-sends a large fixed context on every command, so it is the setting that most changes how slow a turn *feels*. `compaction` is lossy (raise `keep.tokens` when recent detail matters) and `snapshots` costs I/O per step (turning it off stops `/undo` from restoring files). INIT offers `warming` as an explicit opt-in, never silently.

**Agents (`.opencode/agents/`)**: the workers a command dispatches — `spec-implementer` (writes the code + tests of one change from a precise brief; declares `openspec/**`, `.git/**` and `.env*` denied, and no `model:` on purpose so it runs on the parent session's model), `spec-gate` (runs the gate + board), `spec-auditor` (semantic audit of one change; declares `edit`/`shell` denied), `spec-walkthrough` (writes the tech brief; declares writes confined to `openspec/changes/`), `spec-recon` (survey: existing contracts, reuse, zones, overlaps, prior decisions), `spec-explainer` (trace; declares `docs/mechanisms/` as its only write), `spec-deps-graph` (graph + inventory), `diagram-sync` (C4 diff). Model and permissions are declared per agent; the command only routes to it (`agent: <id>` + `subagent: true`). **This build does not enforce those `permissions`** (measured — see `references/status.md`), so the parent verifies the tree after a child returns. A child never approves, signs or decides — and one implementation worker per change (parent or child, never both).

**Gate policy**: pre-commit (hook) → static `gate-check` (seconds). CI on PR → `gate-check --run-tests --diff <base>` + `openspec validate --all --strict`. Before archiving → `gate-check --pre-archive <id>` **OK**. Weekly → advisory semantic pass (`/spec-verify`).

**Code indexing (ladder)**: symbols → the **native LSP tool** (`lsp: true` + `OPENCODE_EXPERIMENTAL_LSP_TOOL=true`); literals → grep; orientation → `build-map.mjs [--root DIR]`, a ~2k-char map (folders → exported names; budget via `SPEC_GROWTH_MAP_CHARS`; regex-based, not a parser — nested or dynamic definitions may be missed; adapted from Ponytail's map, MIT) and the zero-dependency fallback for headless/CI. **Large repos only** (multi-language, deep call graphs): `codebase-memory` — when connected, prefer its graph queries for callers and impact.
